# Technical Feasibility Guide

Evaluate:
- core user journey and must-have capabilities;
- data sources and API availability;
- platform rules and third-party dependencies;
- authentication, permissions, privacy, and security;
- sensitive data and applicable regulation;
- hosting, reliability, backups, and monitoring;
- maintenance and support burden;
- integration complexity;
- migration and lock-in risk.

Classify each major requirement:
- straightforward;
- moderate;
- difficult;
- blocked / unknown.

Recommend the smallest MVP that tests the business hypothesis. Do not design a complex scalable architecture before demand is established.

Technical feasibility is not market validation. “We can build it” does not mean “customers will buy it.”
