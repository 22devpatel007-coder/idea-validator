# Re-score After a Test

Use when the user brings results from interviews, a landing page, a pilot, outreach, or other new evidence for an idea already assessed.

1. Retrieve the earlier assessment, assumption register, and thresholds. If they are not in the conversation, ask the user to paste them or reconstruct them with the user and label them as reconstructed.
2. Compare the results with the thresholds that were set **before** the test. If none were set, say so and treat the conclusion as weaker. Do not invent thresholds after seeing the data.
3. Record sample size, selection method, and limitations. A small, hand-picked sample supports a directional conclusion only.
4. Update the assumption register: mark each tested assumption Tested, Invalidated, or Still open.
5. Re-rate only the affected dimensions, citing the new evidence. Show a before/after table with points and the reason for each change.
6. Re-apply demand caps, overrides, and confidence. State whether the verdict changed.
7. Recommend the next step: scope a narrow MVP (BUILD), run a sharper experiment (TEST), change the segment or offer (MODIFY), or stop (REJECT). Include thresholds for the next step.

If the results are mixed, say which part of the idea they support and which they do not, and avoid rounding up.
